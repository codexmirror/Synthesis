# Sandbox fieldwork

Status: Accepted
Scope: The V1 Sandbox composition, recovery exchange, credential documents,
company maintenance, Sentry, and local checkpoints. Shared identity, discovery,
Access, Session, file-transfer and installation semantics retain their existing
owners. Online does not yet run this composition.

## Gameplay thesis

V0 offered detailed procedures with weak reasons to repeat them. Entry required
knowing an address, reconnaissance repeated several commands, most acquired
software had no immediate purpose, and remote entry/install handoffs interrupted
momentum. Fieldwork makes the next machine desirable through documents that pay,
software that changes available actions, and credentials that connect companies.

The original world remains. Five additional company networks contain real
routers, services, RACK-OS Devices, files, hardware, access relationships and
business identities. Switchboard publishes client reports and requested document
fingerprints. Reports are claims, not live security scans or hidden inventories.

- Relay: initial GhostKey opening, NodeScan 1.2 and an Atlas credential.
- Atlas: patched SSH, Northline credential and RATTLER.
- Northline: AuthGuard, Sentry, slow outbound transfer, current Relay and Meridian keys.
- Foundry: legacy SSH, stronger compute, Rollback, an engineering advisory, a
  GateSSH 1.3.2 package and NODE Miner.
- Meridian: protected SSH, vulnerable RackUpdate, scheduled update activation,
  Foundry credential and a contact document pointing into the existing Bookstore.

Two initial paths are deliberately viable: follow the credential relationships,
or acquire Foundry's update materials and reopen Meridian through RackUpdate.
KeyProbe remains an uncertain alternative against patched SSH. Market purchases
can replace some risky acquisitions. Sandbox prices distinguish these choices;
Online's catalog and prices are unchanged.

## Canonical causes

`createSandboxGameState` enriches the existing authored state at the browser
composition boundary. `GameProvider` itself still defaults to the shared base.
`fieldwork` owns broker requests, delivery receipts and dispatch timing. Each
host owns its credentials and security-maintenance clock. There is no hacked
flag, inventory substitute, or universal action engine.

Investigate composes Ping, Scan and finite endpoint analyses against the
observed SSH/RackUpdate surfaces. A valid existing Access avoids redundant
analysis. It creates neither access nor a Session. Sandbox analyses cost 360
work, or 120 with the exact installed NodeScan 1.2 standard build. Sandbox
Credential Access costs 40% of the base work. RAM and compute scheduling remain
real. Other runtimes retain their existing work costs.

A recovered service-key text file identifies a Device and Service plus a dialed
address and secret. Authentication revalidates the reachable, online endpoint,
open Service and current secret, writes authentication evidence and grants real
DeviceAccess. It preserves prior observations and never starts a Session.
Guessed/invalid/rotated keys cannot establish access. AuthGuard resists probing;
it does not turn a correct maintenance credential into an exploit.

Foundry's concrete advisory, once locally possessed, correlates with remembered
RackUpdate 1.0 evidence to produce UPD-001 Knowledge. Possessing a module alone,
or merely having the target in World Truth, does not teach that weakness.
Rollback, package transfer, pending activation and reboot remain separate causes.

Payment requires a complete local text copy whose content matches the requested
fingerprint. Renaming is harmless; access alone, partial transfers and unrelated
files do not qualify. Settlement debits finite Switchboard escrow, credits the
NODE wallet and records one payment. Files remain on the local Device. Every
three simulated minutes, a round-robin company may issue another document only
if its previous request was delivered. New documents have new file identities
and content; an old copy cannot be sold again. Open requests do not expire.

The security-response clock starts after authentication activity or an accepted
update, rather than cutting a late arrival's session at an arbitrary global
phase. At the deadline, maintenance examines the Device's own history.
When new attempts occurred, it patches GateSSH, rotates service credentials and
revokes Access to that Device. Remote backup-key documents receive new content
and revisioned paths; stolen local copies do not magically update. Player memory
is not rewritten with hidden patch information. A prior local access holder
receives an access-expiry notice. Pending RackUpdate packages cause a real
connectivity-recovery reboot, which owns activation. Sentry on protected company
servers also starts a cleanup clock when a recognized payload is present, even
if there was no new authentication change.

Sentry 1.0 is a concrete package/installation with a deliberately narrow
signature set: RATTLER payload files and NODE Miner executables. It removes
matching files, miner installation records and their running work on the cleaned
Device; packages remain, so reinstallation is possible. A local sweep requires
the exact installed Sentry build. This is not universal malware detection,
firewall protection, or a completed PvP defense model.

## Active interface and continuation

Home prioritizes NodeScan, Software, Files, Market, Processes and Mail. Terminal,
Wallet, Notes and System remain under machine utilities. Software unifies local
packages, installations, modules and recovered keys. Market and remote Files
can start the same local installation operation after an actual download.
Remote package compatibility still describes the remote Device separately.
Sandbox Connect enters the actual foreign firmware directly, preserving the
Shell's keyboard-recovery boundary. RACK-OS starts in Files; its other apps remain.
The file index is derived only inside authorized remote operation.

The browser saves a versioned canonical Sandbox checkpoint every two seconds
and at page exit, independently of Online storage. Reload restores progress;
closed-world time is not simulated. Use one browser tab per Sandbox. New Sandbox
preserves the previous raw checkpoint at `synthesis.sandbox.previous` before
starting over. Incompatible/corrupt checkpoints are not silently replaced. The
current format is a same-version checkpoint, not a supported external import or
long-term migration format. Storage failure is visible.

## Iteration and limits

Fast loop: `npm test -- src/core/game/fieldwork.test.ts src/app/fieldworkFlow.test.tsx src/app/sandboxSave.test.ts`
then play a fresh Sandbox. Run the affected retained-mechanics tests when those
mechanics change; CI owns broad validation. Viewport/Terminal tests use a fixed
world so company timing and Home taxonomy cannot invalidate keyboard proofs.

Current limits: authored initial populations and loot; recurring documents do
not introduce new industries or unique software forever; no shared-world V1
intents, no PvP, no offline simulation. Sentry is narrow and local checkpoints
have one previous backup. Full Online parity is explicitly deferred.
