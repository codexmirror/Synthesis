# V0 scope

V0 is the responsive NODE-OS foundation for Synthesis. It contains a freshly created, versioned and sliced in-memory game state; a home launcher; shared status bars; and separate Terminal, Network, Processes, Wallet, Notes, Files, and System launcher apps. These apps describe the current interface, not a permanent product taxonomy.

Terminal supports command parsing, command history, and the `help`, `clear`, `ip`, `status`, `scan <ipv4|network-name>`, `inspect <ipv4|network-name>`, and `analyze <ipv4:port>` commands. Scan explores outward to discover relationships, connected targets, and represented open services; Inspect looks inward to report one target’s own properties without enumerating services. The current loop uses `ip`, scans that address to reveal the real `home-net` relationship, scans `home-net` to discover responding represented members, then scans the LAN server to discover SSH on TCP/22 and HTTP on TCP/80. Complete service endpoints are actionable copy-only Target Tokens; Analyze resolves them to stable device and service identities. The network has a stable identity distinct from its name and canonical stable-ID membership containing the player's device and that existing LAN server. Device and service identities are likewise distinct from mutable IP, name, and port attributes.

IPv4 scans distinguish `SELF` (the player-owned device), `LAN` (another device sharing a represented local network with SELF), and `REMOTE` (a represented device without that shared membership). A device Scan reveals real LocalNetwork relationships derived from canonical membership and open exposed services derived from device-owned state, while a network Scan discovers responding represented members and deterministically omits offline members. Results retain stable target identities internally while Terminal presents useful current attributes only. Device Inspect reports address, scope, online status, self hardware where owned, and server identity where represented; it does not report membership or services. Network Inspect reports its current name and whether SELF is connected, without enumerating members. Scan observations and Terminal text are not entities or game state. Successful SSH Service Analysis records only positive, stable-ID vulnerability Knowledge with a historical display label; HTTP analysis records no negative knowledge. Actionable names and addresses in Terminal facts and discoveries use one Target Token presentation and copy their exact visible value without inserting or executing a command. Service names and protocols remain plain presentation; only the complete endpoint is actionable. Hostnames, ranges, access/filesystem gameplay, malware, scanner upgrades, and multiplayer remain unimplemented. The graphical Scan app uses the same observation and Service Analysis domain semantics as Terminal through a local application boundary to present a local Networks → Devices → Services workspace; its navigation remains local presentation state while observations grow canonical Discovery rather than Knowledge. Terminal output scrolls internally while its prompt remains outside that scrolling region. Notes persist locally through a feature-owned browser adapter, and the Notes textarea owns its scrolling. Files is a small virtual read-only listing.

On narrow or coarse-pointer layouts, focusing editable text activates a dedicated Editing presentation sized from the visible viewport. The shell changes its chrome and application presentation for keyboard use rather than allowing the entire shell to scroll; explicitly marked application regions own vertical scrolling. An opt-in viewport diagnostic (`?viewportDebug=1`) is retained for internal mobile investigation and is not player-facing gameplay.

Shell navigation remains outside game state. Service Analysis is the first production Process consumer: serializable completed/required work advances from elapsed time at the application boundary. CPU capacity controls work throughput; running jobs share CPU headroom equally. RAM capacity controls admission and is reserved only while jobs run. The Processes app observes active resource use and concrete completed results. Completed history can be cleared manually without removing running Processes or reversing consequences retained in Knowledge or World state. Completion resolves exactly once against current world truth. Processes execute only on the local device, and there are no saves, migrations, remote compute, backend, authentication, real networking, exploit/access gameplay, broader hacking, economy simulation, or multiplayer systems.

See [`ARCHITECTURE.md`](ARCHITECTURE.md) for the dependency and identity boundaries established by V0.

### Discovery memory

Scan observations now grow an additive, session-persistent Discovery slice. Scan opens on intrinsic SELF only and browsing known networks, devices, and services does not scan. Network and device scans are explicit actions; remembered service details retain their observed endpoint and Analyze remains bound to that observation. World Truth, Discovery, and deeper Knowledge remain separate canonical concepts.
